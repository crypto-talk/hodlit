# 관리자 투표 삭제 (HODL-116)

`/admin/polls?room=ETH`의 현재 투표에서 삭제를 선택한다. 확인 창에 방·투표 번호·진행/종료 상태와 질문을 표시하며,
확인할 때만 `DELETE /api/v1/polls/{id}`를 호출한다. 취소하면 요청하지 않는다. 요청 중에는 중복 클릭과 확인 창 취소를 막는다.

종료된 투표는 기존 `GET /api/v1/polls/{id}`를 이용해 번호로 찾는다. 선택은 `?room=ETH&poll=42`로 남아
새로고침·뒤로 가기에도 복원된다. 현재 투표를 닫으면 그 번호를 자동으로 선택해 종료 투표를 바로 삭제할 수 있다.
관리자 전용 전체 투표 목록 API는 없으므로 전체 보관 목록을 만든 것으로 표시하지 않는다.
조회한 투표가 선택한 방과 다르면 삭제 버튼 대신 해당 방의 확인 링크를 표시한다.

삭제 대상은 확인 창을 연 시점의 객체로 고정한다. 이후 현재 투표 조회가 바뀌더라도 다른 투표를 삭제하지 않는다.
번호는 양의 안전한 정수만 받고, 응답의 번호·방·진행 상태를 확인할 수 없으면 삭제 대상으로 사용하지 않는다.
조회 응답의 표 수·선택지별 득표 수·참여 내역은 관리 화면용 타입에서 버린다.

## 응답과 갱신

- 204는 빈 본문으로 처리하고, 삭제한 현재/조회 투표 캐시를 비운 뒤 다시 조회한다.
- 현재 관리자 투표·번호 조회, 방/홈 투표, 지난 결과, 내 투표 기록의 하위 캐시를 함께 무효화한다.
- 404는 이미 삭제됐거나 존재하지 않는 투표로 안내하고 재조회한다. 삭제 성공 토스트는 표시하지 않는다.
- 401은 로그인 만료로 안내하고 선택 주소를 `next`에 담아 로그인 화면으로 이동한다. 공통 HTTP 래퍼의 기존 401 갱신 규칙을 따른다.
- 403은 관리자 권한 오류로 안내한다. 그 밖의 서버 오류는 기존 오류 설명을 표시하고, 네트워크 실패는 재조회로 결과를 확인하도록 안내한다.
- 응답이 유실됐을 수도 있으므로 실패 후에도 캐시를 갱신한다. 성공하지 않은 요청을 성공으로 안내하거나 자동 삭제 재시도를 추가하지 않는다.

서버의 논리 삭제·권한·집계 제외 계약은 HODL-115를 그대로 사용한다. 백엔드와 생성된 API 타입은 변경하지 않는다.

## 확인 방법

프론트 디렉터리에서 순서대로 실행한다.

```sh
pnpm exec tsc --noEmit
pnpm run lint
pnpm test
NEXT_PUBLIC_API_URL=http://127.0.0.1:18080 pnpm run build
NEXT_PUBLIC_API_URL=http://127.0.0.1:18080 pnpm run test:html
pnpm exec playwright install chromium
pnpm run test:e2e:polls
```

브라우저 테스트는 빌드된 Next 서버를 13000 포트로 띄우고 브라우저의 API 응답을 가로챈다. 실제 서버 데이터를 변경하지 않는다.
확인·취소, 중복 클릭, 204, 종료 투표 조회·새로고침, 기존 생성·종료, 401/403/404/500, 다른 방 투표를 확인한다.
종료 투표 시나리오는 390px 모바일 화면에서도 실행한다. 단위 테스트는 API 메서드·빈 응답·집계 제거·번호 검증과
날짜/사용자/쪽이 다른 투표 캐시의 무효화를 확인한다.

실제 API 연결은 별도 로컬 Rust/PostgreSQL 환경에서 로그인, 현재/종료 투표 삭제와 지난 결과·내 기록 제외를 확인한다.
운영 계정·데이터로 수행하는 삭제 검증은 포함하지 않는다.
