# 프론트 이용 기록 수집 (HODL-89)

프론트가 PostHog 로 보내는 이벤트와 설정을 적는다. 코드는 `frontend/lib/analytics/` 에 있다.
이 문서는 **프론트 쪽 절반**이다. 서버 성공 이벤트, 분석용 식별자, 대시보드, 수집 고지는 아직 없다(아래 "남은 일").

## 켜고 끄기

| 변수                            | 기본값                                                    | 설명                                                                     |
| ------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------ |
| `NEXT_PUBLIC_ANALYTICS_ENABLED` | 없음(꺼짐)                                                | `true` 일 때만 켜진다                                                    |
| `NEXT_PUBLIC_POSTHOG_KEY`       | 없음                                                      | 이벤트 수집용 프로젝트 토큰(`phc_…`). 개인 API 키를 넣지 않는다          |
| `NEXT_PUBLIC_POSTHOG_HOST`      | `https://us.i.posthog.com`                                | 수집 호스트. EU 프로젝트면 `https://eu.i.posthog.com`                    |
| `NEXT_PUBLIC_ANALYTICS_ENV`     | 빌드가 production 이면 `production`, 아니면 `development` | 이벤트의 `environment` 값. Vercel 미리보기 배포는 `preview` 로 따로 준다 |

켜는 변수와 키가 둘 다 있어야 켜진다. 꺼져 있으면 SDK 를 내려받지도 않고, 추적 호출은 아무 일도 하지 않는다.
SDK 를 못 불러오거나 전송이 실패해도 화면 동작에는 영향이 없다.

## 보내는 이벤트

프론트는 화면이 실제로 보인 순간만 보낸다. 가입 · 지갑 연결 · 인증 · 글 · 댓글의 성공은 서버 몫이고 프론트에서 보내지 않는다.

| 이벤트              | 시점                                                                                                      | 속성                               |
| ------------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `room_viewed`       | 운영 중인 방 화면이 정상으로 보였을 때                                                                    | `room_symbol`, `source`            |
| `post_viewed`       | 글 상세 내용이 정상으로 보였을 때                                                                         | `post_id`, `room_symbol`, `source` |
| `room_closed_shown` | 닫힌 방(공사 중) 안내가 보였을 때. 방 화면 · 글 상세 · 글 수정 · 방 뉴스 · 지난 투표에서 같은 안내를 쓴다 | `room_symbol`, `source`            |

모든 이벤트에 붙는 것: `event_id`(UUID), `occurred_at`(UTC ISO), `environment`, `schema_version`(지금 1).

- `source` 는 직전에 본 화면의 종류다: `direct`(사이트에 처음 들어온 화면) · `home` · `room` · `post` · `search` ·
  `profile` · `mypage` · `write` · `admin` · `other`. 주소는 보내지 않는다.
- `event_id` 는 전송 직전에 PostHog 이벤트의 `uuid` 로도 옮긴다. 재전송되어도 같은 값이라 PostHog 가 중복을 거른다.
- 시각은 PostHog 의 이벤트 시각을 기준으로 분석한다. `occurred_at` 은 브라우저 시계라 참고용이다.
- 같은 화면이 다시 그려지거나 개발 모드에서 effect 가 두 번 돌아도 한 번만 센다. 방 안에서 쪽 · 탭을 바꾸는 것도
  다시 세지 않는다. 다른 화면에 갔다 돌아오거나 새로고침하면 다시 센다.

## 보내지 않는 것

- 자동 클릭 수집, 자동 페이지뷰, 세션 녹화, 설문, 히트맵, 오류 수집, 기능 플래그는 전부 끈다.
- 전송 직전에 한 번 더 거른다(`events.ts` 의 `scrub`): 위 세 이벤트와 `$identify` 가 아니면 버리고,
  SDK 가 스스로 붙이는 주소 · 유입 경로 · 문서 제목 속성(`$current_url` · `$referrer` · `$pathname` · `$host` 등)과
  사람 속성(`$set` · `$set_once`)을 지운다.
- 이메일 · 닉네임 · 지갑 주소 · 회원 번호 · 글과 댓글 내용 · 검색어 · 토큰은 어디에도 넣지 않는다.
- 남는 SDK 기본 속성: 브라우저 · OS · 기기 종류 · 화면 크기 · 언어 · 시간대 · User-Agent · 익명 기기 식별자 · 세션 식별자.
  IP 는 SDK 설정으로 끌 수 없다. PostHog 프로젝트 설정의 "Discard client IP data" 로 끈다.

## 사용자 식별

- 비로그인 방문은 SDK 의 익명 식별자를 쓴다. 사람 프로필은 만들지 않는다(`person_profiles: identified_only`).
- 로그아웃하면 `reset` 한다. 같은 브라우저의 다음 사용자 행동이 이전 계정에 붙지 않는다.
- **로그인 식별은 아직 하지 않는다.** 서버가 정한 분석 전용 식별자가 있어야 하는데 지금 응답에 없다.
  내 정보 응답(`/auth/*` · `/me`)에 `analyticsId` 가 생기면 그 값으로 `identify` 하도록 연결해 두었다.
  회원 번호나 닉네임으로 대신하지 않는다.

## 확인한 것

- 가짜 API 서버에 붙여 브라우저로 방 · 글 · 닫힌 방을 열어 세 이벤트가 나가는 것, 속성에 주소 계열이 없는 것,
  `uuid` 가 `event_id` 와 같은 것을 전송 내용에서 확인했다.
- 꺼진 상태로 빌드와 화면이 그대로 동작한다.
- 실제 PostHog 프로젝트로는 보내 보지 않았다.

## 남은 일

- PostHog 프로젝트 생성, 토큰과 호스트 확정, Vercel 환경변수 설정
- 서버 성공 이벤트(`signup_completed` 등)와 분석 전용 식별자 — 백엔드
- 수집 고지 · 동의 문구, 보관 기간, 삭제 요청 절차
- 대시보드 5종
- 운영 사이트에 CSP 가 생기면 `connect-src` 에 수집 호스트를 넣는다. 프론트 설정(`next.config`)에는 지금 CSP 가 없다
- 봇으로 보이는 브라우저(헤드리스 등)의 이벤트는 SDK 가 버린다. 자동화 테스트로 확인할 때는 일반 User-Agent 를 쓴다
